Zwei Beispielprojekte: Minimum und Maximum

Die Bridge hat eine unangenehme Eigenschaft: sie kann sehr wenig und sehr viel. Diese Seite zeigt beide Enden an lauffähigem Code — erst das absolute Minimum, dann alles, was man heute deklarieren kann. Beides liegt im Repository unter example/minimal/ und example/maximum/ und wurde headless ausgeführt.

1. Minimum: drei Dateien, ein Aufruf​

Mehr braucht es nicht. Kein Python-File, keine Konfiguration, kein Wrapper.

mein_projekt/
├── project.godot
├── addons/
│   └── python_bridge/      ← Release-ZIP hierher entpacken
├── main.tscn
└── main.gd

project.godot — die zwei Zeilen, die das Plugin beim Aktivieren selbst schreibt:

[autoload]

PythonBridge="*res://addons/python_bridge/core/python_bridge.gd"

main.gd — das ist der komplette Code:

extends Node

func _ready() -> void:
	var started := await PythonBridge.start_instance()
	if started.is_error():
		push_error(started.error_message())
		return
	var result := await PythonBridge.execute("result = 6 * 7")
	print("6 * 7 = ", result.value)   # 6 * 7 = 42.0

Was dabei automatisch passiert:

SchrittWerDauer
Python suchen (python_executable → PYTHON_PATH → PATH)Bridgesofort
venv im Workspace anlegen, websockets installierenProvisionerbeim ersten Start 1–3 min
Server-Prozess starten, WebSocket + HandshakeBridgedanach ~1 s
Code ausführen, Ergebnis zurückExecutorMillisekunden

Das ist bewusst die untere Grenze: kein Skript auf der Platte, keine Einstellungen, keine Struktur. Für „einmal etwas ausrechnen“ reicht das dauerhaft.

2. Maximum: alles deklarieren, was es gibt​

Dasselbe Projekt, nur mit allen Registern. Die folgenden Blöcke sind keine Wunschliste, sondern der aktuelle Stand von PythonBridgeConfig.defaults() — jeder Schlüssel existiert und wirkt.

2.1 Wo die Werte stehen können​

OrtReichweiteTypischer Einsatz
Projekt → Projekteinstellungen → Python Bridgeim Projekt, auch im ExportProjekt-Defaults, die das Team teilt
<workspace_dir>/config.jsonpro ArbeitskopieCI, Server, generierte Projekte
PythonBridge.configure({…})Laufzeit-CodeSonderfälle, Tests, Bootstrapping

Präzedenz beim Start (später gewinnt): Defaults → Projekt-Einstellungen → config.json → configure().

project.godot mit gesetzten Projekt-Einstellungen:

[python_bridge]

general/autostart=false
general/workspace_dir="res://python_bridge"
general/python_executable=""
general/dependencies="numpy,scipy"
general/hot_reload_mode="reload_context"
general/auto_generate_wrappers=false

config.json im Workspace (überschreibt die Projekt-Einstellungen):

{
  "autostart": true,
  "dependencies": ["numpy", "scipy", "pandas"],
  "task_timeout_ms": 120000,
  "data_ref_threshold_bytes": 8388608
}

2.3 Zwei Instanzen statt einer​

for instance in ["default", "worker"]:
	var started := await PythonBridge.start_instance(instance)
	if started.is_error():
		push_error("Start von %s fehlgeschlagen: %s" % [instance, started.error_message()])
		return

"worker" ist ein eigener Python-Prozess mit eigenem Kontext, eigener Speicherbelegung und eigener Crash-Domäne. Aufrufe wählen die Instanz als letztes Argument:

await PythonBridge.call_script("max_stats", "describe", [werte], {"bins": 4}, "worker")

2.4 Ein .py-Skript, das seine Pakete selbst deklariert​

# scripts/app_stats.py
import numpy as np

__bridge_deps__ = ["numpy"]          # Top-Level, Position in der Datei frei


def describe(values, bins=8):
    arr = np.asarray(values, dtype="float64")
    hist, edges = np.histogram(arr, bins=bins)
    return {"count": int(arr.size), "mean": float(arr.mean()),
            "std": float(arr.std()), "hist": hist.tolist(), "edges": edges.tolist()}


def big_matrix(n=64):
    """Ergebnis über der DataRef-Schwelle: kommt als Handle an."""
    return np.arange(n * n, dtype="float64").reshape(n, n)

2.5 Ein .pyx-Modul daneben​

# scripts/fastmath.pyx
__bridge_deps__ = []


def dot(list a, list b):
    cdef double total = 0.0
    cdef int i
    for i in range(len(a)):
        total += a[i] * b[i]
    return total

Der Aufruf ist identisch zum .py-Fall — der Build läuft automatisch davor (oder explizit über compile_cython()).

2.6 DataRef statt Payload​

Mit data_ref_threshold_bytes = 4096 rutscht ein 64×64-float64-Ergebnis (32 KiB) über die Schwelle und kommt als Handle an:

var result := await PythonBridge.call_script("max_stats", "big_matrix", [64])
if result.value is PythonBridgeDataRef:
	var ref := result.value as PythonBridgeDataRef
	print(ref.kind, ref.dtype, ref.shape, ref.nbytes)   # ndarray float64 [64, 64] 32768
	var bytes := await PythonBridge.materialize_data(ref)
	# bytes.value ist ein typisiertes Array (hier 64 Zeilen à 64 float64)
	PythonBridge.release_data(ref)

2.7 Signale, Introspection, Aufräumen​

PythonBridge.instance_state_changed.connect(
	func(instance: String, state: String) -> void: print(instance, " -> ", state))
PythonBridge.task_done.connect(func(task: PythonBridgeTask) -> void: print(task.id))
PythonBridge.bridge_event.connect(
	func(instance: String, event: Dictionary) -> void: print(instance, event))
PythonBridge.pulse.connect(func() -> void: pass)

var schema := await PythonBridge.introspect_script("max_stats")
for entry in schema.value:
	print(entry["name"], entry["params"])          # describe, big_matrix

Was davon wirklich nötig ist​

KategorieSchlüssel
PflichtAutoload, await start_instance() — alles andere hat Defaults
Fast immer sinnvollworkspace_dir (im Export user://), dependencies, task_timeout_ms
Nur bei Bedarfworkers_per_instance, Batching, data_ref_threshold_bytes, Retries, hot_reload_mode
Nur im Web-Exportweb_* (Pyodide-Runtime, Pakete, Bundle-URLs)
Reserviertprovision_venv_timeout_ms, provision_pip_timeout_ms, auto_generate_wrappers, wrapper_dir

Alle Schlüssel im Detail: Konfiguration. Die API hinter den Beispielen: API-Referenz.
